**`src/queries.ts`** — new `getPersonAdjustments(adjustedBy, start, end)` returning `PersonAdjustmentRow[]` (store, product, units delta, reason, timestamp), filtered by person over a half-open `[start, end)` date range across all stores/products, most recent first. **`prisma/schema.prisma`** — per the project rule to declare an index for each new access pattern, I added `@@index([adjustedBy, adjustedAt])` on `InventoryAdjustment`. The two existing indexes lead with `storeId` and `adjustedAt` respectively, so neither can serve an equality-on-person + range-on-time query; leading with `adjustedBy` satisfies both in one traversal. A comment documents the reasoning alongside the existing index notes.

One design note for whoever builds the page/route: the range is half-open (`gte start`, `lt end`), so pass the day *after* the last day of interest as `end` to include the full final day.
