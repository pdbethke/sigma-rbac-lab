## Inventory adjustments page — done

The `InventoryAdjustment` model already carried every field the page needs (who, product, store, delta, reason, timestamp), so the changes were small:

**`prisma/schema.prisma`** — added a standalone index so the month-wide, cross-store lookup is supported (the existing `[storeId, productId, adjustedAt]` composite can't serve a query that doesn't filter by store, mirroring how `InventoryDaily` has its own `@@index([snapshotDate])`):
```prisma
@@index([adjustedAt])
```

**`src/queries.ts`** — added Page 5, `getLargestAdjustmentsThisMonth()`, built the same way as the existing pages (Prisma `select` with nested relations, JS post-processing like Page 4). It returns `adjustedBy`, `productName`, `storeName`, `unitsDelta`, `reason`.

Two design points worth flagging:
- **"Largest" = largest magnitude.** A −500 correction is a bigger adjustment than a +10, so results are ranked by absolute delta. Since Prisma can't `ORDER BY abs()`, I fetch the 10 most-positive and 10 most-negative deltas of the month and rank their union in JS — provably contains the true top-10-by-magnitude, and bounded to ≤20 rows.
- **"This month"** = the current calendar month computed at call time (`[first-of-month, first-of-next-month)`).
