## Notes on design choices

- **`prisma/schema.prisma`** models the full `ProductType → ProductFamily → ProductLine → Product` hierarchy, plus `Brand`, `Store`, `InventoryDaily` (all specified fields), and `InventoryAdjustment`. `InventoryDaily` has a `@@unique([snapshotDate, storeId, productId])` (one row per snapshot/store/product) and indexes tuned to the four pages (`[storeId, snapshotDate]`, `[isLowStock]`, `store.region`, etc.).
- **`src/queries.ts`** exports one typed function per page, each returning exactly the fields the page asks for. Query 1 first resolves the store's latest snapshot date, then fetches that date's rows. Query 4 uses `groupBy` with `_sum` on `inventoryValue`, then resolves store names.

Everything typechecks (`tsc --noEmit` clean) and runs. To reproduce from scratch: `npm install && npx prisma migrate dev && npx prisma db seed`, then `npx ts-node src/smoke.ts`.

Two small additions beyond the letter of the spec — the seed and smoke test — exist only so the queries could be *verified*, not just written. Say the word if you'd rather I strip them down to just `schema.prisma` + `queries.ts`.
