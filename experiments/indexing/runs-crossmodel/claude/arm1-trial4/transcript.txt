## Schema notes
- Product hierarchy modeled as `ProductType → ProductFamily → ProductLine → Product`, with `Brand → Product` separate.
- `InventoryDaily` has `@@unique([snapshotDate, storeId, productId])` — one row per store/product/day — plus indexes on `snapshotDate`, `storeId`, `productId`, `isLowStock`, and `region` on `Store`, so the four queries hit indexes rather than scans.
- Booleans (`isStockout`, `isLowStock`) map to SQLite integers automatically; dates to `DateTime`.

## The four functions (all in `src/queries.ts`)
1. **`getStoreCurrentInventory(prisma, storeId)`** — finds the store's latest `snapshotDate`, returns product name, brand name, product family name, units on hand. Verified: returns the Aug-2 value (12), not the stale Aug-1 value (90).
2. **`getRegionLowStock(prisma, region, snapshotDate?)`** — every `isLowStock` product across a region → store name, product name, units on hand. Defaults to the region's latest snapshot; optional date to pin it.
3. **`getProductAdjustmentHistory(prisma, storeId, productId)`** — full history newest-first, including `adjustedBy` (who).
4. **`getRegionalSummary(prisma, region, snapshotDate)`** — `groupBy` store summing `inventoryValue`, ordered descending. Verified: East Main 41 (6+35), East River 4.

Each takes a `PrismaClient` argument so callers own connection lifecycle and the functions are trivial to test.

To run it yourself: `npm install && npx prisma migrate dev --name init && npx ts-node src/smoke.ts`.
