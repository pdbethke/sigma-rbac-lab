# Verification checklist

Every claim the published app makes, as a number. `expected/verification_matrix.csv` is generated by
the oracle, so the sentence in the UI and the test are the same value and neither can drift.

Regenerate with `python3 oracle/build.py`.

## The matrix

```
user_name          nav  res  my_inventory  current  low  write  stores  audit
Public User          2    1             0        0    0      0       0      0
Aaliyah Kowalski     3    1        31,500      150    0      0       0      0
Priya Cohen          4    2        94,500      450   16      0       0      0
Mateo Boateng        5    3        31,500      150   15      1       1      0
Kwame Bianchi        6    4        31,500      150    0      1       1      1
```

Read each column against the corresponding element while acting as that user.

    nav             Nav Source                  what the switcher offers
    res             Resolution                  granted rows for this identity
    my_inventory    My Inventory                the tenant boundary, all snapshots
    current         Current Inventory           latest snapshot only
    low             Needs Attention             Is Low Stock on the latest snapshot
    write           Write Gate                  may this identity post at all
    stores          Inventory Postable Scopes   what the store dropdown may offer
    audit           Audit Gate                  may this identity see the audit trail

## What each row proves

**Public User** — zero everywhere except nav. The anonymous principal reaches Home and Profile and
sees no inventory, no form, no audit trail. Not blocked: the rows were never in the result set.

**Aaliyah** — 31,500 rows and zero write. Same store as Kwame, same read access, no Data Entry page
and nowhere to post. Read and write are separate questions.

**Priya** — 94,500 across all three stores, and still zero write. Global *view* is not global
authority.

**Mateo vs Kwame** — the pair worth clicking. Identical `my_inventory` (31,500) and identical
`current` (150), entirely different rows. **Count proves scoping is happening; only the store name
proves it is the right scoping.** Several bugs in this build hid behind numbers that looked correct.

**needs_attention** — 15 for Mateo, 0 for Kwame, 16 for Priya (Alhambra's 15 plus Albuquerque's 1).
Two managers on the same page, one with a queue of work and one with none.

**audit** — 1 for Kwame alone. His auditor grant is global, which is exactly why the store dropdown
must pin `Resource Key = "inventory"`: without it, global audit authority widens his inventory
options to every store.

## Integrity checks — all must be zero

    invalid_adjustments      a post outside the author's write scope
    invalid_serials          a serial recorded against a multi-unit delta
    invalid_serial_format    a serial not matching its resolved pattern

Each has been made to fail deliberately, so an empty result means the check works rather than that
it was never exercised. See Step 22 in `BUILD_LOG.md`.

## Before publishing

1. Identity control reset to **Public User** — publishing snapshots it as the shipped default
2. Publish, then **Make app public**
3. Read the published URL in a private window and confirm the Public User row above
4. Then switch through the other four and confirm the rest

Step 3 is the one that matters. Every number in this repo was read from an editor session unless it
says otherwise, and this workbook has already shipped a gated table to the public link once.
